# Self-hosting BACKSTAGE

BACKSTAGE is a **single-user** personal-assistant PWA: one passkey-protected
account, all data in local JSON files under `data/`. It is not multi-tenant —
if several people must use the same instance, they share one account.

Two supported paths:

- **Docker** (recommended, any host) — see [Run with Docker](#run-with-docker)
- **Node directly** (VPS, cPanel, bare metal) — see [Run with Node](#run-with-node)

---

## 1. Requirements

| Tool | Version | Notes |
| --- | --- | --- |
| Node.js | >= 20.9 | production runtime |
| Bun | 1.x | required by `bun run setup` and the one-command installer |
| Git | any | |
| Docker + Compose | optional | only for the Docker path |

An **OpenAI-compatible API endpoint + key** is required for the chat
(`NEXT_PUBLIC_API_URL` / `IA_API_KEY`). Everything else is optional.

`/install.sh` is served by every instance at `https://<your-domain>/install.sh`,
so self-hosters can point the one-liner at their own domain.

## 2. Install

One command (checks prerequisites, clones, installs, generates secrets, starts):

```bash
curl -fsSL https://brain.mprnl.fr/install.sh | bash
```

Options: `--node` (start with Node instead of Docker), `--no-start` (prepare
only), `--help`. Environment: `BACKSTAGE_DIR` (target directory, default
`./backstage`), `BACKSTAGE_PORT` (local port, default `3000`). The script only
ever clones the official repo, installs dependencies and generates local
secrets — no `sudo`, no telemetry.

Prefer to see what happens? Same thing, step by step:

```bash
git clone https://github.com/MattiaPARRINELLO/backstage.git
cd backstage
bun install
cp .env.example .env.local
bun run setup        # generates AUTH_SECRET, SETUP_TOKEN, VAPID keys, WebAuthn vars
bun dev              # http://localhost:3000
```

`bun run setup` is idempotent: it never overwrites a value already present in
`.env.local`, and re-running it keeps the same secrets.

Then:

1. Open <http://localhost:3000/login>.
2. Register your passkey. `SETUP_TOKEN` protects that first registration: it can
   be used **once**. The login page reads it from the `?setupToken=…` query
   parameter and sends it as the `x-setup-token` header, so open
   <http://localhost:3000/login?setupToken=VOTRE_TOKEN>.
3. Fill in `NEXT_PUBLIC_API_URL` and `IA_API_KEY` in `.env.local` and restart.

### Environment variables

Full template with comments: [`.env.example`](../.env.example).

**Required**

| Variable | Role |
| --- | --- |
| `NEXT_PUBLIC_API_URL` | OpenAI-compatible endpoint used by the chat |
| `IA_API_KEY` | API key of that endpoint |
| `AUTH_SECRET` | signs session JWTs (generated by `bun run setup`) |
| `WEBAUTHN_RP_ID` / `WEBAUTHN_ORIGIN` | passkey domain/origin (`localhost` / `http://localhost:3000` locally) |
| `SETUP_TOKEN` | one-time protection of the first passkey registration |

**Optional** — Google (Gmail/Calendar), Microsoft To Do, OpenWeatherMap,
Brave search, CESAR timetable, VAPID push, `CRON_SECRET` +
`CRON_BASE_URL` for `/api/cron/*`.

### Security notes

- **`SETUP_TOKEN` is not optional in production.** Without it, the server
  refuses the first passkey registration with HTTP 503 rather than let the first
  visitor take ownership of the account.
- `proxy.ts` denies everything by default: only `/`, `/login`, `/offline`,
  `/privacy`, and `/api/auth`, `/api/cron`, `/api/push`,
  `/api/reminders/pending` are public. Verify `GET /api/…` returns `401` on your
  deployment.
- Never commit `.env.local` or `data/` (both gitignored). Back up `data/` — it
  holds every account, token and cache.
- The app assumes it serves one person: expose it behind HTTPS and keep it
  closed to the internet except through your own auth or private network.

## 3a. Run with Docker

```bash
cp .env.example .env.local
bun run setup
docker compose up -d --build
```

- The app listens on <http://localhost:3000> — use `BACKSTAGE_PORT=8080
  docker compose up -d --build` if that port is taken.
- `compose.yaml` passes every variable of `.env.local` into the container and
  mounts `./data` as a volume, so updates keep your data.
- Rebuild with `docker compose up -d --build`.

Production behind a domain:

```bash
# .env.local
WEBAUTHN_RP_ID=backstage.example.com
WEBAUTHN_ORIGIN=https://backstage.example.com
GOOGLE_REDIRECT_URI=https://backstage.example.com/api/auth/google/callback
MICROSOFT_REDIRECT_URI=https://backstage.example.com/api/auth/microsoft/callback
CRON_BASE_URL=https://backstage.example.com
```

Put a TLS reverse proxy (Caddy, nginx, Traefik) in front of port 3000 — passkeys
and Web Push require HTTPS.

`NEXT_PUBLIC_VAPID_PUBLIC_KEY` is inlined at **build** time. If push matters,
pass it to the build (docker compose forwards it automatically):

```bash
docker build --build-arg NEXT_PUBLIC_VAPID_PUBLIC_KEY="$(grep ^NEXT_PUBLIC_VAPID_PUBLIC_KEY .env.local | cut -d= -f2)" -t backstage .
```

## 3b. Run with Node (VPS / cPanel)

```bash
bun install            # or npm install
bun run build
bun run start          # or: npm run start
```

`next.config.ts` uses `output: "standalone"`, so on shared hosting you can copy
`.next/standalone`, `.next/static`, `public/` and `assets/` into the app folder
and start `node server.js` with `PORT=3000`. The cPanel procedure, including the
crontab lines for the daily brief and reminders, is documented in
[`deploy-cpanel.md`](./deploy-cpanel.md).

## 4. Optional integrations

| Integration | What it needs | If missing |
| --- | --- | --- |
| Gmail + Calendar (Google) | OAuth client + redirect URI | Gmail/calendar tools report not-connected |
| Microsoft To Do | Azure app registration | reminders stay local only |
| Weather | `OPENWEATHERMAP_API_KEY` | daily brief omits the weather block |
| Web search | `BRAVE_SEARCH_API_KEY` | falls back to DuckDuckGo |
| CESAR timetable | `CESAR_USERNAME` / `CESAR_PASSWORD` | schedule tool says no sync yet |

The app starts and answers on every protected page without any of these; the
AI chat only needs the endpoint + key.

## 5. Backups & updates

- Back up `data/` (it contains `users.json`, OAuth tokens, `memory.json`,
  `config.json`).
- Update: pull, `bun install`, rebuild, restart. Keep `AUTH_SECRET` and
  `VAPID_PRIVATE_KEY` stable or every session and push subscription is lost.

## 6. Troubleshooting

| Symptom | Cause |
| --- | --- |
| 503 on the passkey registration | `SETUP_TOKEN` not set on the server |
| "Non authentifié" on every API | session cookie missing/expired — log in again |
| Chat reports an AI configuration error | `NEXT_PUBLIC_API_URL` / `IA_API_KEY` missing or wrong |
| Push never arrives | VAPID keys changed between builds, or no `VAPID_SUBJECT` |
| Passkey fails with a domain error | `WEBAUTHN_ORIGIN` does not match the URL in the browser |
| `docker compose` fails with "port is already allocated" | another service uses 3000 — run `BACKSTAGE_PORT=8080 docker compose up -d --build` |
| `bun run setup` cannot find bun | install Bun first (see requirements); the installer never does it for you |
